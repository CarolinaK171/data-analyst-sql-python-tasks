# 1. Primary Keys датасета `source.zip`: описание и обоснование выбора

| No | Table Name | Primary Key | Primary Key Selection Rationale&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; |
| :---: | :--- | :--- | :--- |
| 1 | `countries` | `country_id` | Каждой стране назначается свой уникальный номер ID, который однозначно идентифицирует определенную страну и не может повторяться для разных стран |
| 2 | `cities` | `city_id` | Здесь и далее по аналогии с `countries` из п. 1 — каждому городу назначается свой уникальный номер ID, который однозначно его идентифицирует |
| 3 | `categories` | `category_id` | Каждой категории соответствует свой уникальный номер ID, который однозначно ее идентифицирует |
| 4 | `products` | `product_id` | Каждому продукту соответствует свой уникальный номер ID, который однозначно его идентифицирует |
| 5 | `shops` | `shop_id` | Каждому магазину соответствует свой уникальный номер ID, который однозначно его идентифицирует |
| 6 | `employees` | `employee_id` | Каждому работнику присваивается свой уникальный номер ID, который однозначно его идентифицирует |
| 7 | `customers` | `customer_id` | Каждому клиенту присваивается свой уникальный номер ID, который однозначно его идентифицирует |
| 8 | `sales` | `sales_id` | Каждая строка таблицы `sales` описывает факт продажи конкретного продукта в определенном магазине конкретному покупателю в определенный момент времени и фиксируется в системе с помощью уникального номера ID.<br><br><sub>*Примечание: в качестве альтернативного первичного ключа также может рассматриваться `transaction_number`, который уникальным образом идентифицирует каждую строку / транзакцию в таблице.*</sub> |
